# H.264 / H.265 专利风险备忘（独立于版权许可证）

> 本文件只讨论**专利**，不重复 `SOURCE.md` 的版权许可内容。二者是独立的法律维度：
> 取得 GPLv3 授权 ≠ 取得任何专利授权；反之亦然。

## 背景

ffmpeg runtime（`128263-g9f9b9548583`，evermeet tessus 构建）包含：

- H.264：`--enable-libx264`（编码器）与 `--enable-libopenh264`（编码器），
  解码器为 FFmpeg 内置（`h264` decoder）。
- H.265/HEVC：`--enable-libx265`（编码器），解码器为 FFmpeg 内置（`hevc` decoder）。

## 风险点（逐项，均不可由版权合规消除）

1. **H.264 / H.265 专利池**：MPEG LA / Access Advantage / VIA LA 等对 H.264 与 HEVC
   的实现（编码与解码）持有大量专利。在部分司法辖区，**分发**实现这些编解码的
   软件可能需要专利许可。是否需要、由谁取得，取决于分发范围/地区/商业安排，
   属 `LEGAL_REVIEW_REQUIRED`。
2. **x264 / x265 无专利授权**：二者是 GPL 许可的**开源实现**，其许可证只授予版权权利，
   **不包含任何专利授权条款**（GPLv3 第 11 条的专利条款仅覆盖贡献者自身持有的专利，
   不覆盖第三方专利池）。不能以"x264 是开源的"推定免除专利责任。
3. **libopenh264 陷阱（重要）**：Cisco 在 [OpenH264 项目](https://www.openh264.org/)
   中为其**自行预编译并经 Cisco 分发的二进制**向 MPEG LA 付费取得专利授权。该授权
   **只覆盖 Cisco 官方分发的二进制**。本 runtime 是**从源码静态编译**进 ffmpeg 的
   openh264，**不适用** Cisco 的专利授权——此点最易被误读，特此显式声明。
4. **静态链接加重暴露面**：构建为全静态（`--pkg-config-flags=--static`），
   编解码器直接编入分发二进制，专利"实现"发生在分发的二进制内，不存在
   "动态加载、用户自备"的缓冲论点。

## 与版权许可的分离声明

- GPLv3（版权）材料：见 `SOURCE.md` 与 `LICENSE-GPL-3.0.txt`。
- 专利事务状态：**`LEGAL_REVIEW_REQUIRED`** —— 在法律审查给出结论前，
  任何对外分发行为都应将本节视为未决风险。
- 本文件不构成法律意见。

## 审查输入清单（供法律顾问使用）

1. `BUILD_CONFIG.txt`（实际启用的编解码器开关全集）。
2. 分发形态：官方 catalog 发布归档 + 桌面端 Runtime Store 落地。
3. 分发地区与商业模式。
4. 是否可裁剪构建（如仅需封装/转码容器而无 H.265 编码，可评估去除
   `--enable-libx265` 的定制构建以收缩专利暴露面）。
